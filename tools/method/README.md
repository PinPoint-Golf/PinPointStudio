# tools/method — the refactor method's tools

Five small tools the refactor method depends on. Each has a header saying how to run it, and each but `build_times.sh` a `--self-test` that runs on fixtures in a temporary directory; ctest runs the self-tests in the Gui suite (`src/Gui/tests/CMakeLists.txt`).

**`im_excerpt.py`** — prints the part of the information model (`docs/developer/information_model.md`) a brief needs: §10 (ownership) whole, the row or heading that defines each id given, and the footnotes those cite. The coordinator writes it into a brief's `IM-*.md` excerpt, so an implementing agent reads that excerpt and never the whole model (about 100k tokens). `python3 tools/method/im_excerpt.py ID [ID ...] > IM-x.md`; `--im <path>` reads another copy. ctest: `im_excerpt_selftest`.

**`one_at_a_time.sh`** — the machine-wide heavy-work lock. Every build, ctest run, lint run and app probe on the development Mac runs through it, so that only one runs at a time across every lane and worktree (the machine has 16 GB). The lock is a `mkdir` folder at `<main checkout>/build/.heavy.lock`, found from git's common dir, so a copy run from any worktree takes the same lock; a lock whose holder has died is reclaimed. `tools/method/one_at_a_time.sh <command...>`; `--print-lock` prints the path. ctest: `one_at_a_time_selftest`.

**`im_changelog_merge.py`** — resolves information-model changelog clashes when one lane's change is rebased onto another's: where both sides of a conflict are a single changelog row, it keeps both and renumbers the second to the next free version; any other conflict is left in place and reported (exit 1). `python3 tools/method/im_changelog_merge.py docs/developer/information_model.md`, mid-rebase. ctest: `im_changelog_merge_selftest`.

**`cabin_run.sh`** — runs an item's full test suite, both passes, on the studio PC (24 cores, `jom -j16`) from the Mac, so the Mac builds the item and runs only the item's own suites and the lints. `tools/method/cabin_run.sh <worktree> [jobs N] [--wait]`. It refuses a worktree whose HEAD is not on `origin/main` (the cabin pulls main), makes the worktree's patch with `tools/studio/make-wip-patch.sh`, and takes the cabin lock (a `mkdir` folder at `/mnt/swingdata/scratch/cabin.lock`; a holder older than its ceiling is reclaimed). It refuses (21) a worktree that changes `tools/studio/studio-build.cmd`, since the cabin always runs main's copy. It waits while a jom, a ctest, or a cmd.exe running `studio-build.cmd` or a scratch-share `.cmd` already runs there. It then launches `studio-build.cmd tests` detached, after a pull that the wrapper does first. It then polls through the share and prints a summary: the exit code, both passes' counts, each failing test with its first failure line, and the build time. A busy studio (PinPoint Studio, Foresight, FSX, GSPro) exits 20, BUSY; `--wait` retries every 10 min. The summary goes to `<worktree>/build/cabin-runs/`. The run dir under `/mnt/swingdata/scratch/` is deleted on a pass and kept otherwise. Once launched, the lock is kept until that run's `rc.txt` has been read, even if the Mac side is interrupted or gives up (exit 22 or 23); the next runner reclaims it when that run is over. The script's header has the exit codes. ctest: `cabin_run_selftest` (a fake cabin; `cabin_run_samples/` holds real cabin output).

**`build_times.sh`** — times the test tree's builds on the studio PC, so a stage can show its build times are no worse: a clean build, a one-header edit (`src/Core/pp_debug.h`, then `src/Vocabulary/Analysis/swing_analysis.h`) and a link (one test's `.cpp`), each a run of `studio-build.cmd build` (the tests mode's cmake and jom, with no ctest pass) at `jom -j16`, behind the cabin lock. `tools/method/build_times.sh <worktree> [--no-clean] [--repeat] [jobs N] [--dry-run]`; it writes one table (seconds, compiles, links) to `<worktree>/build/build-times/<sha>.txt`. Run it before and after a change with the same options and compare the rows; `--repeat` times the last header twice to show the noise. The script's header says what each step does. No self-test: `--dry-run` prints the cabin wrappers and touches nothing.
**The move tool** is `tools/refactor/move_files.py`, with the kept context check `tools/refactor/context_check.py`: every scripted move of the platform refactor, as a map, with `--dry-run`, `--verify` and a self-test (ctest `move_files_selftest`). See `tools/refactor/README.md`.
