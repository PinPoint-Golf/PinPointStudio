# tools/method — the refactor method's tools

Six small tools the refactor method depends on. Each has a header saying how to run it, and each but `build_times.sh` a `--self-test` that runs on fixtures in a temporary directory; ctest runs the self-tests in the Gui suite (`src/Gui/tests/CMakeLists.txt`).

**`im_excerpt.py`** — prints the part of the information model (`governance/artefacts/information_model.md`) a brief needs: §10 (ownership) whole, the row or heading that defines each id given, and the footnotes those cite. The coordinator writes it into a brief's `IM-*.md` excerpt, so an implementing agent reads that excerpt and never the whole model (about 100k tokens). `python3 tools/method/im_excerpt.py ID [ID ...] > IM-x.md`; `--im <path>` reads another copy. ctest: `im_excerpt_selftest`.

**`one_at_a_time.sh`** — the machine-wide heavy-work lock. Every build, ctest run, lint run and app probe on the development Mac runs through it, so that only one runs at a time across every lane and worktree (the machine has 16 GB). The lock is a `mkdir` folder at `<main checkout>/build/.heavy.lock`, found from git's common dir, so a copy run from any worktree takes the same lock; a lock whose holder has died is reclaimed. `tools/method/one_at_a_time.sh <command...>`; `--print-lock` prints the path. ctest: `one_at_a_time_selftest`.

**`im_changelog_merge.py`** — resolves information-model changelog clashes when one lane's change is rebased onto another's: where both sides of a conflict are a single changelog row, it keeps both and renumbers the second to the next free version; any other conflict is left in place and reported (exit 1). `python3 tools/method/im_changelog_merge.py governance/artefacts/information_model.md`, mid-rebase. ctest: `im_changelog_merge_selftest`.

**`cabin_run.sh`** — runs an item's full test suite, both passes, on the studio PC (24 cores, `jom -j16`) from the Mac, so the Mac builds the item and runs only the item's own suites and the lints. `tools/method/cabin_run.sh <worktree> [jobs N] [--wait]`. It refuses a worktree whose HEAD is not on `origin/main` (the cabin pulls main), makes the worktree's patch with `tools/studio/make-wip-patch.sh`, and takes the cabin lock (a `mkdir` folder at `/mnt/swingdata/scratch/cabin.lock`; a holder older than its ceiling is reclaimed). It refuses (21) a worktree that changes `tools/studio/studio-build.cmd`, since the cabin always runs main's copy. It waits while a jom, a ctest, or a cmd.exe running `studio-build.cmd` or a scratch-share `.cmd` already runs there. It then launches `studio-build.cmd tests` detached, after a pull that the wrapper does first. It then polls through the share and prints a summary: the exit code, both passes' counts, each failing test with its first failure line, and the build time. A busy studio (PinPoint Studio, Foresight, FSX, GSPro) exits 20, BUSY; `--wait` retries every 10 min. The summary goes to `<worktree>/build/cabin-runs/`. The run dir under `/mnt/swingdata/scratch/` is deleted on a pass and kept otherwise. Once launched, the lock is kept until that run's `rc.txt` has been read, even if the Mac side is interrupted or gives up (exit 22 or 23); the next runner reclaims it when that run is over. The script's header has the exit codes. ctest: `cabin_run_selftest` (a fake cabin; `cabin_run_samples/` holds real cabin output).

**`build_times.sh`** — times the test tree's builds on the studio PC, so a stage can show its build times are no worse: a clean build, a one-header edit (`src/Core/pp_debug.h`, then `src/Vocabulary/Analysis/swing_analysis.h`) and a link (one test's `.cpp`), each a run of `studio-build.cmd build` (the tests mode's cmake and jom, with no ctest pass) at `jom -j16`, behind the cabin lock. `tools/method/build_times.sh <worktree> [--no-clean] [--repeat] [jobs N] [--dry-run]`; it writes one table (seconds, compiles, links) to `<worktree>/build/build-times/<sha>.txt`. Run it before and after a change with the same options and compare the rows; `--repeat` times the last header twice to show the noise. The script's header says what each step does. No self-test: `--dry-run` prints the cabin wrappers and touches nothing.

**`make_rtm.py`** — writes the requirements traceability matrix, `governance/artefacts/rtm.md`, from committed source files only: `requirements.md`, `uc-map.csv`, the observations register, the issue snapshot (`rtm_issues.json`), the accepted gaps, the baseline, the kind defaults and the platform gate lists, beside every test registration, `pp_requirement(<test> <ID>...)` call (`tests/cmake/PinPointTests.cmake`) and `// REQ:` line in a `tst_*.qml` file, grepped from the source. `python3 tools/method/make_rtm.py` writes the page; `--check` fails when it is stale or on a flag outside the accepted gaps and the baseline; `--init` writes the baseline once; `--rename <old> <new>` carries a mechanical rename of an unlabelled test into the baseline, swapping its one line, since a rename needs no new label (BT-39), and refuses, with the reason, unless the old name is in the baseline and registered nowhere and the new one is registered, unlabelled and not in the baseline; `--refresh-issues --library <the library folder>` (the only mode that uses the network, through `gh`) rewrites the snapshot, titles included, and writes nothing, naming each issue, when a title it would keep names a golfer (a name read from the library's athlete and session folders, never written or printed); `--platform-list <ctest tree> <platform>` writes a platform's gate list. A test name built in a loop that the tool cannot expand is listed in `rtm_loop_tests.txt`. The page reads in this order: the summary; the requirements, area by area, each with its words, status, the evidence present and missing in words, its tests, observations and issues (with titles), and its corpus swings as one line, the count then the count by date (no per-swing list and no build: the build stays in `rtm_observations.csv`); the flags in words, and the warnings; the controls, labelled tests and documents; every gap last, its baseline key in small print. Every requirement id carries its Requirement sentence, shortened to about 12 words, every control id its first sentence, and every issue number its title; the wording never changes a gap's key. The header lists the thirteen flags. ctest: `rtm_check` and `rtm_selftest`.

**`artefact_paths_check.py`** — not a tool but a check: fails when a tracked file still cites a governing document at the path it had before #195 moved it into `governance/artefacts/` (an old path, an old file name that changed, or a markdown link to an old home); the dated records that keep the old spelling are listed in it with a reason. It checks its own matcher on every run instead of a `--self-test`. ctest: `artefact_paths_check`.

**The move tool** is `tools/refactor/move_files.py`, with the kept context check `tools/refactor/context_check.py`: every scripted move of the platform refactor, as a map, with `--dry-run`, `--verify` and a self-test (ctest `move_files_selftest`). See `tools/refactor/README.md`.
