# D. Domain screens and flows — duplicate findings

Scope: `src/Gui/{athlete,home,monitor,calibration,setup(+pages,parts),session,cameras,imu,media,viz,swing3d,shot,shell,diagnosticmodel}` (126 app files, about 40,000 lines), read on 19 Oct 2026 with the repo being edited concurrently. Read-only; every line number is as seen. Counts come from grep or `inventory.json`.

How to read this file. Reports A (primitives) and B (containers) were written in parallel and already cover most of the generic copy-paste that happens to sit in this cluster (toggles, `ScopedAction`, `DevicePill`, popup chrome, avatar, topo background, selectable tiles, `PpMicro`). I confirmed those against my own reading and list the cluster-specific instances in the table at the end (section "Confirmed from A and B"). D1 to D15 are the findings that are new in this report or where this cluster adds material the other reports do not have. They are ranked by value.

Ranking logic: first things that can produce wrong behaviour (D1), then the largest measured copy-paste (D2, D3, D4), then medium consolidations, then dead code and census findings.

### D1. Device-health rules are re-derived in four places, with the thresholds hard-coded, although the C++ already has the answer
- **Verdict:** TRUE DUPLICATE (logic, not layout). Contains one possible latent defect, see below.
- **Where:**
  - "Connected sensor is calibrated": `imu/PpImuPanel.qml:50` and `session/PpSessionToolbar.qml:97` (`_imuCalibratedOk`, character-for-character the same expression: `anatCalibrated && mountDeviationDeg <= 15.0 && mountGravityErrorDeg <= 25.0`); `calibration/WitmotionArmRoutine.qml:410` (same two thresholds inside the per-segment check); `tests/setup/fakes/FakeImuInstance.qml:43` (test double repeats it).
  - "Sensor connection gave up": `imu/PpImuPanel.qml:295` (`stateLabel === "Error" || stateLabel === "Not found"`), `session/PpSessionToolbar.qml:88`, `setup/SetupContext.qml:331`. Matching on the driver's display string in three files.
  - "Any connected sensor needs calibration" loop: `PpImuPanel.qml:55-62` and `PpSessionToolbar.qml:106-113` (same loop over `imuDeviceList`/`instanceFor`). "Any selected camera not fixed in place": `cameras/PpCameraPanel.qml:49-56` and `PpSessionToolbar.qml:70-77`. "All enabled devices connected" / `startConnect` / `disconnectAll`: `PpImuPanel.qml:67-110` and `PpCameraPanel.qml:150-180` (same shape, different manager).
- **What is duplicated:** `imu/imu_instance.h:92-96,164-169` already exposes `fullyCalibrated` (`m_anatCalibrated && deviation <= kMountDeviationMaxDeg(15) && gravity <= kMountGravityErrorMaxDeg(25)`), and its comment says "the check a setup page must use rather than re-deriving it from the three properties above". `setup/SetupContext.qml:374` and `setup/SetupDraft.qml:109` do use it. The two toolbar files do not; they re-derive it with literals. The "failed" rule and the aggregate loops exist in three and two copies and will drift the moment a driver label changes.
- **Possible latent defect (needs a `--probe-qml` check before anyone relies on it):** `imuManager.instanceFor()` returns an `ImuDeviceBase*` that is an `HmInstance` for a HackMotion (`imu/imu_manager.h:306-313`). `HmInstance` has `anatCalibrated` but no `mountDeviationDeg`/`mountGravityErrorDeg` (grep of `hm_instance.h/.cpp`: none). In QML `undefined <= 15.0` is `false`, so `_imuCalibratedOk(hmInstance)` is always `false` and a connected wG3 would count as "needs calibration" in the toolbar IMU pill and `ImuRow` even after a good calibration. I did not run it, so treat as unverified.
- **Shared component it should fold into:** move the three predicates into `ImuManager` as invokables or properties (`bool needsCalibration`, `bool anyFailed`, `bool allEnabledConnected`, per-device `calibratedOk(id)` that is vendor-aware), and the camera equivalents into `CameraManager`. Both panels and the toolbar then bind to one property each. `SetupContext.devices` already computes `failed`/`connecting`; the manager version should be the single source for it too.
- **Effort / risk:** S to M. The QML side shrinks by about 70 lines; the C++ side is small. Risk is the vendor-aware rule (HM calibration state vs Witmotion mount checks) and the tests in `tests/setup` that fake `ImuInstance`.
- **Confidence:** high that the duplication exists; medium-low that the HackMotion path is actually wrong at runtime.
